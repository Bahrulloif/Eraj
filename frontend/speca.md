## Что уже есть

Голый Vite + React 19 + TypeScript шаблон (`npm create vite`), почти не тронутый:
- `src/App.tsx` — сломанный черновик (импортирует `useState` неправильно, вызывает

- Никакого роутинга, API-клиента, стилей, авторизации — всё с нуля.
- Папка **не под git** (`/home/admin/workspace/maxshop` — не репозиторий; `Eraj/` — отдельный
  git-репозиторий сам по себе). Git для фронта — отдельный решаемый вопрос, не блокирует работу.

## Бэкенд, с которым интегрируемся

`Eraj/` — см. `../CLAUDE.md` за полным контекстом. Коротко, что важно для фронта:
- Base URL в dev — `http://localhost:5056` (профиль `http` в `launchSettings.json`) либо любой
  порт, на который реально поднят `dotnet run --project WebApi` (в этой сессии чаще использовался
  `5080` через `--urls` — сверяться по факту, не считать один порт истиной).
- JWT Bearer, без валидации Issuer/Audience. Роли: `SuperAdmin`, `Admin`, `Marketing`, `User`,
  `Businessman`, `Courier`.
- **CORS не настроен на бэкенде вообще.** Решение: Vite dev-прокси (`vite.config.ts`
  `server.proxy`) на `/api` и `/Images` — фронт всегда ходит на свой же origin, браузер CORS не
  видит. В проде это станет задачей реверс-прокси (nginx/etc.) — не блокирует dev-разработку,
  отдельный пункт ближе к концу плана.
- 11 товарных сущностей (`Car`, `Motorbike`, `Truck`, `SpareAccessorTransp`, `NoteBook`,
  `SmartPhone`, `Tablet`, `SpareAccessorKomp`, `Apartment`, `CommercialRealEstate`, `Cottage`),
  каждая — свой контроллер, свои DTO-поля, но одинаковый паттерн CRUD-маршрутов (с вариациями в
  именовании — сверять по факту в каждом контроллере, не считать маршруты одинаковыми "по
  аналогии").
- `Response<T>` — `{ data, message, errors, statusCode }`; списочные эндпоинты — `PagedResponse<T>`
  добавляет `pageNumber/pageSize/totalPage/totalRecord`.
- Владение (`OwnerId`/`ApplicationUserId`) и роли уже полностью защищены на бэкенде (см. чек-лист
  `Eraj/README.md`, пройден полностью) — фронту **не нужно** дублировать эту логику ради
  безопасности, только ради UX (скрыть недоступные кнопки, не заставлять ловить 403 в рантайме).

## Ключевые решения по стеку (сделаны, не переспрашивать)

| Вопрос | Решение | Почему |
|---|---|---|
| Роутинг | `react-router-dom` (v7+, data router) | Стандарт для SPA такого размера, официально поддерживается React 19. |
| HTTP-клиент | Нативный `fetch`, обёрнутый в один тонкий модуль `src/api/client.ts` | Проект небольшой, `axios` — лишняя зависимость ради интерцепторов, которые несложно написать самим. |
| Состояние сервера (кэш/загрузка/ошибки списков) | Свои простые хуки (`useQuery`-подобный, но самописный, ~40 строк) | `@tanstack/react-query` — оправданная опция, но осознанно не тянем ещё одну крупную зависимость, пока не станет больно без неё. Если по ходу дела ручной кэш начнёт течь — пересмотреть. |
| Глобальное состояние | React Context: `AuthContext` (юзер+токен), `CartContext` (счётчик корзины в шапке) | Масштаб не требует Redux/Zustand — два контекста и локальный state страниц достаточно. |
| Стили | Обычный CSS с custom properties (design tokens в `:root`), файл на компонент/страницу (`Button.css` рядом с `Button.tsx`) | Уже используемый в шаблоне подход (`App.css`), без доп. зависимостей (Tailwind, styled-components) и их конфигурации. Переоценить, если вёрстка станет громоздкой. |
| Формы | Неконтролируемые/контролируемые по месту, без `react-hook-form` | Форм немного и они не супер-сложные (кроме, может, товарных Add/Update с ~15-40 полями — туда `react-hook-form` может зайти позже, отдельным решением при реализации). |
| Иконки | `public/icons.svg` (уже есть, спрайт) — `<use href="/icons.svg#name">` | Уже в шаблоне, ноль доп. веса. |

```
│   └── ProtectedRoute.tsx # редирект на /login если не авторизован; опц. проверка роли
├── components/             # переиспользуемые вне конкретной страницы: Header, Footer, Pagination,
```

## Карта страниц / маршрутов

Публичное (без авторизации, `AllowAnonymous` на бэке — сверено с чек-листом бэка):
- `/` — главная: 3 каталога, возможно "популярное"/"горячие скидки" (`RatingAndTop` уже есть на
  бэке — `HotDiscount`, `PopularCategory`, `PopularProduct`, `HitOfThe{Day,Month,Year}`).
- `/catalog/:catalogId` — категории каталога
- `/category/:categoryId` — подкатегории категории
- `/products/:productType?subCategoryId=..` — список товаров одного из 11 типов, с пагинацией и
  базовыми фильтрами (у каждого типа свой набор фильтров — сверять с бэковым `GetXFilter`, не все
  одинаковые)
- `/products/:productType/:id` — карточка товара
- `/login`, `/register`

Требует авторизации (`User` и выше):
- `/profile` — просмотр/редактирование профиля
- `/addresses` — CRUD адресов
- `/delivery-addresses` — CRUD адресов доставки (привязаны к `addresses`)
- `/cart` — корзина, оформление в заказ
- `/orders`, `/orders/:id` — список и детали своих заказов
- `/recommended` — `RecommendedProduct` (персонализированная лента, требует юзера)

Требует роли `Businessman` (и выше):
- `/my-listings` — свои объявления по всем 11 типам в одном месте
- `/my-listings/:productType/new`, `/my-listings/:productType/:id/edit` — форма добавления/
  редактирования товара с загрузкой картинок

Требует `Admin`/`SuperAdmin`:
- `/admin/catalog` — управление `Catalog`/`Category`/`SubCategory`
- `/admin/roles` — назначение ролей юзерам (`RoleService`)

    ```nginx
    server {
        listen 80;

        root /var/www/maxshop/frontend/dist;
        location / {
            try_files $uri $uri/ /index.html;

        # (nginx вместо Vite), сами префиксы /api и /Images остаются ровно теми же.
        location /api/ {
            proxy_pass http://localhost:5056;
            proxy_set_header Host $host;
        }
        location /Images/ {
            proxy_pass http://localhost:5056;
        }
    }
    ```
    Если в реальном деплое такой прокси невозможен (фронт и бэк вынужденно на разных origin —
    например, разные облачные сервисы без общего входа) — тогда и только тогда придётся добавить
